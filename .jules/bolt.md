# Bolt's Journal

## 2026-11-11 - Eliminating Redundant Gate Filtering in duck_envelopes
**Learning:** `speechmix.envelopes.duck_envelopes` computes keyframe envelope points by evaluating both `covering_masks` (which speaker masks another) and `duck_masks` (which microphone needs ducking). Both helper functions independently called `_gates(grid, settings)`, which stacks active/level arrays across all speakers, computes dominance thresholds, and runs `open_windows` and `trim_end` across every lane. In typical sessions (e.g. 30 to 77 minutes with 2 to 4 speakers), calling `_gates` twice doubled gate calculation runtime for completely identical inputs. Allowing `covering_masks` and `duck_masks` to accept precomputed gates (`_gates_precomputed`) and computing `_gates` once in `duck_envelopes` cuts `duck_envelopes` execution time by ~1.75x across 2 to 4 speakers (e.g. 9.71 ms -> 5.45 ms on 30 min 2-speaker, 18.92 ms -> 10.91 ms on 30 min 4-speaker, 24.76 ms -> 14.06 ms on 77 min 2-speaker) with 100% bit-for-bit output parity.
**Action:** When a high-level pipeline function coordinates multiple mask or timeline analyses that depend on an expensive shared gate or filter state, expose an optional precomputed parameter on the lower-level analysis functions and evaluate the shared state once at the orchestrating level.

## 2026-11-11 - Vectorized Run Filtering in speechmix.masks (open_runs & close_gaps)
**Learning:** In timeline mask processing routines such as `open_runs` (filtering bursts shorter than confirmation time `k`) and `close_gaps` (closing unvoiced gaps shorter than a threshold), the operations previously called `runs(mask.astype(np.int8))` to produce full Python tuple lists `[(start, end, val), ...]`, iterating over every single segment with Python loops and scalar conditions. On long podcast timelines (e.g. 77 minutes = ~231,000 frames with 2,000+ transitions), this incurred thousands of tuple allocations and Python branching checks for mostly unaffected segments. Vectorizing the condition over boundary indices directly (`out[starts] & ((ends - starts) < k)` for `open_runs`; `(~out[starts]) & (starts != 0) & (ends != out.size) & ((ends - starts) < limit)` for `close_gaps`) and iterating only over the targeted slices reduces execution time by 2.1x–2.8x for `open_runs` and 1.7x–2.5x for `close_gaps`, and accelerates end-to-end `duck_masks` evaluation by ~1.34x (70.9 ms -> 53.0 ms) while maintaining exact mathematical equivalence.
**Action:** When filtering or modifying boolean mask intervals by duration or condition, do not generate full tuple lists of all segments; find run boundaries with `np.flatnonzero(arr[1:] != arr[:-1]) + 1`, filter the candidates using vectorized boolean array masks, and slice only the filtered intervals.

## 2026-11-10 - Subsampled Frame RMS in speechmix.grid.speech_grid
**Learning:** `speechmix.grid.speech_grid` builds per-frame speech presence and level decisions across raw microphone stems. Previously, it called `dsp.moving_rms(padded, frame)` on each stem, executing a dense sliding window filter (`uniform_filter1d`) and elementwise square-root across all raw audio samples (e.g. 8.64 million samples per stem for a 3-minute episode at 48 kHz), only to immediately discard ~99.9% of the values when downsampling to frame centers at hop intervals (`idx = np.minimum(np.arange(n_frames) * hop + hop // 2, n_samples - 1)`). Evaluating window sums directly at the sampled frame centers via cumulative sums `(cs[idx + frame] - cs[idx]) / frame` avoids dense per-sample filtering, eliminates intermediate float64 full-length square root buffers, and speeds up `speech_grid` by ~1.85x (184.2 ms -> 99.0 ms on 1 minute stereo, 607.0 ms -> 328.0 ms on 3 minutes stereo) with exact numerical parity across all sample rates and stem lengths.
**Action:** When computing moving statistics (such as RMS or average power) on high-sample-rate timelines that are subsequently downsampled to coarse control-rate grids (e.g. hop = 20 ms), do not compute dense sliding filters across all audio samples; evaluate window sums directly at the required frame center indices using cumulative sums or prefix arrays.

## 2026-11-09 - Vectorizing First Ramp Candidate Evaluations in nhsx.fades._fit_two
**Learning:** `nhsx.fades._fit_two` fits a 2-segment raised-cosine ramp to volume curves (e.g. music bed rises). While candidate endpoints `e` for the second segment had already been vectorized, candidate start points `a` for the first segment were still iterated sequentially via a Python loop (`for a in range(m):`), executing individual NumPy ufuncs (`clip`, `cos`, `log10`, `max`, `where`) for every single start candidate. For an 8.5 s rise with ~85 grid steps, this incurred ~3,500 inner Python iterations and repeated function calls. Slicing all valid start candidates `a` simultaneously into a 2D broadcasted array of shape `(num_valid_a, len(w_first))` and broadcasting first and second ramp errors with `np.maximum(first_err[:, None], sec_err[None, :])` allows NumPy to compute all candidate combinations natively in C. This reduces `_fit_two` runtime by ~3.0x (from ~127.6 ms down to ~43.0 ms per call on an 8.5 s rise) while remaining 100% bit-for-bit identical across all curves.
**Action:** In two-stage parameter searches over 1D time grids, vectorize both stages across time slices rather than only the outer or inner parameter: evaluate stage 1 over $(A \times T_1)$ and stage 2 over $(B \times T_2)$, then combine their error arrays using 2D outer broadcasting `np.maximum(err_a[:, None], err_b[None, :])` and `np.unravel_index(np.argmin(...))`.

## 2026-11-08 - Piecewise Segment Evaluation in speechmix.envelopes.duck_gain
**Learning:** `speechmix.envelopes.duck_gain` converts sparse dB envelope breakpoints into audio sample gain factors. Previously, it constructed a full-length 64-bit `timeline` array with `np.arange` across the entire clip, evaluated `np.interp` across every individual audio sample, and exponentiated the full-length buffer `(10.0 ** (curve / 20.0))`. On standard material (e.g. 10 to 30 minutes at 48 kHz), this allocated 230–700 MB of temporary 64-bit float arrays per call and spent 1.1s to 3.3s evaluating plateaus and outer margins that were mostly constant 0 dB. By calculating segment boundary sample indices with `math.ceil((t + base) * rate - low)`, flat 0 dB spans stay untouched (initial unity gain), flat non-zero plateaus and margins are filled directly in-place with scalar exponentiated gain, and linear ramp evaluation is confined solely to the short transition slices where `v0 != v1`. This runs ~17x-31x faster (~1.10s -> ~0.064s on 10 minutes; ~0.99s -> ~0.031s for 10x on 1 minute) and eliminates hundreds of megabytes of intermediate array allocations while remaining 100% bit-identical.
**Action:** When converting piecewise linear breakpoint envelopes to audio-rate arrays, do not evaluate dense interpolations across the entire timeline; map breakpoints to sample boundary indices with `math.ceil`, fill flat plateaus directly in-place, and only compute linear ramps on the transition slices.

## 2026-11-07 - Failed: Parallelizing speechmix.chain.deess via ThreadPoolExecutor
**Learning:** `speechmix.chain.deess` already used `ThreadPoolExecutor(max_workers=1)` to pipeline the per-chunk low-pass filter (sosfilt, main thread) with the numba gain kernel (worker thread). Attempts to increase to `max_workers=2` (133 ms vs 111 ms for 1 minute of stereo 48 kHz audio) or remove the thread pool entirely (125 ms vs 111 ms) both regressed. The per-chunk tasks (~1–3 ms each) are too short for additional thread pipelining to overcome thread management overhead; `max_workers=1` was already the sweet spot.
**Action:** `ThreadPoolExecutor(max_workers=1)` in `deess` is intentionally optimal; do not change. Future parallelism gains in this function would require restructuring to submit multiple kernels ahead (overlapping kernel k+1 with kernel k), which is unsafe because the `follow` follower state is shared between consecutive kernels.

## 2026-11-06 - Eliminating Intermediate Array Allocations in envelope_at with bisect
**Learning:** `speechmix.envelopes.envelope_at` interpolates volume envelope curves at a scalar timestamp `when`. Previously, each scalar query rebuilt a full list of timestamps from `points` via list comprehension (`times = [t for t, _ in points]`) and passed it to `np.searchsorted`. For a Python list of `(t, v)` points, this incurred an $O(N)$ heap allocation and Python list + NumPy array boxing overhead for every single point query. Replacing `np.searchsorted` with the standard library `bisect.bisect_left(points, when, key=lambda p: p[0])` performs the binary search in $O(\log N)$ time directly over the existing list with zero intermediate allocations. Across realistic envelope point counts (e.g. 200 points for a multi-span track), querying the envelope improved by ~19x (~20.2 µs -> ~1.05 µs per query; up to 63x on 1000 points) while remaining exact.
**Action:** When performing scalar lookups or point interpolations over sorted Python list structures, avoid extracting temporary key lists or delegating to NumPy search functions that convert Python lists to arrays; use standard library `bisect` with a `key` selector to achieve $O(\log N)$ lookup with zero allocation overhead.

## 2026-11-05 - Direct float32 Linear Blending in speechmix.mixlaw
**Learning:** `speechmix.mixlaw.mix_blend` cross-fades raw and wet float32 audio buffers based on dxRevive's non-linear mix curve. It previously upcast both inputs to float64 (`raw.astype(np.float64)` and `aligned.astype(np.float64)`), which allocated two full 64-bit temporary arrays and a 64-bit sum array before downcasting back to float32. For standard multi-channel audio buffers (e.g. 30 seconds of stereo 48 kHz audio), this ballooned peak allocation from ~22 MB to ~44 MB (2.0x overhead) and took ~32.2 ms. Blending directly in float32 with an in-place addition (`np.multiply(raw, w_dry, out=out); out += w_wet * aligned`) and fast-pathing exact identity endpoints (`mix == 0.0` and `mix == 1.0`) avoids the 64-bit allocations and runs ~3.1x faster (~10.3 ms vs ~32.2 ms) with identical float32 output precision.
**Action:** When performing linear combinations on float32 audio buffers where the destination type is float32, avoid upcasting to float64 for intermediate arithmetic unless precision bounds require double precision; scale and accumulate into preallocated buffers to halve memory usage and cut computation time.

## 2026-11-05 - Vectorizing Run-Length Interval Extraction in speechmix.masks
**Learning:** `speechmix.masks.runs()` generates `(start, end, value)` intervals from boolean/integer timeline mask arrays. The endpoints were originally indexed element-by-element in a Python list comprehension (`[(int(bounds[i]), int(bounds[i+1]), int(values[bounds[i]])) for i in range(bounds.size - 1)]`), which repeated scalar indexing, boundary checks, and `int()` boxing per segment. By slicing the vector bounds array once (`starts = bounds[:-1]`, `ends = bounds[1:]`, `vals = values[starts]`) and using `.tolist()` combined with `zip(..., strict=True)`, the extraction runs ~3.5x-4.0x faster without changing return types or tuple layouts.
**Action:** When extracting run spans or intervals from transition indices in NumPy arrays, slice the array bounds into vectorized start, end, and value sub-arrays and convert them via `.tolist()` rather than indexing individual elements in Python loops.

## 2026-11-04 - Vectorizing Grid Search in nhsx.fades
**Learning:** `nhsx.fades.long_segments()` performs grid search (`_fit_two` and `_fit_run`) to find optimal raised-cosine `<Fade>` ramp parameters matching volume curves. The inner search originally looped over combinations of candidate start, middle (junction), and end times in Python, executing individual NumPy ufuncs (`clip`, `cos`, `log10`, `max`) per combination (~90,000 inner iterations in `_fit_two` for a typical 8-second rise). Because the error calculation on the second segment depends only on the junction step `m` and endpoint step `e`, all candidate endpoints `e` can be evaluated simultaneously in a 2D broadcasted array across time points. This reduces the number of NumPy array evaluations from ~90,000 to $O(S)$ vectorized operations without altering the search space or math.
**Action:** When performing 1D parameter grid search over interval endpoints, check if inner segments decouple from earlier loop variables. Vectorizing the candidate bounds in 2D array slices eliminates Python loop interpretation and function dispatch overhead.

## 2026-11-02 - Decouple Independent Multi-Ramp Curve Fitting Searches
**Learning:** In piecewise curve-fitting algorithms over time-ordered grids such as `nhsx.fades._fit_two`, the breakpoint partitions input samples into independent ramp segments. Evaluating each ramp's error separately avoids recomputing full-window errors for every parameter combination. An earlier implementation measured ~17x faster (~3.88 s to ~0.20 s) on an 8.5 s rise; `main` now vectorizes endpoint candidates as well.
**Action:** For multi-ramp fits, partition at the junction and calculate each segment's error independently before combining the errors; vectorize candidate bounds where possible.
