## 2026-11-02 - Floating file browser dialog semantics and dismissal pattern
**Learning:** In vanilla JS single-page companion apps (like Podcast Magic), file pickers implemented as absolutely positioned overlay containers (`.browser`) frequently omit ARIA dialog semantics (`role="dialog"`, `aria-modal="false"`, `aria-haspopup="dialog"`, `aria-controls`, and `aria-expanded`) and standard dismissal affordances (Escape key, backdrop/outside clicks, and header Close buttons). Without these, keyboard-only users become trapped inside the overlay without an obvious escape route or return-focus target, and screen reader users aren't informed that a modal or popup dialog has opened or closed.
**Action:** When implementing or enhancing popup file pickers or floating overlays, always wire `aria-haspopup="dialog"`, `aria-expanded`, and `aria-controls` on the opener, pair with `role="dialog"` on the container, provide Escape key and outside-click dismissal, and automatically return focus to the trigger element when the dialog closes.

## 2026-11-01 - Keyboard focus visibility in shared UI styling
**Learning:** Shared design systems across paired companion apps (autoraffkat and Podcast Magic) often rely on custom `:focus-visible` styling (`var(--accent)` outline) to keep keyboard navigation accessible without adding unwanted focus rings for pointer clicks. When styling custom buttons (`.tabs button`, action buttons) on dark themes, native browser focus outlines can blend into dark backgrounds or be completely suppressed by default button resets unless `button:focus-visible` is explicitly declared.
**Action:** When working on web interfaces in this repo, ensure `button:focus-visible` is styled consistently with inputs using `outline: 2px solid var(--accent); outline-offset: 1px;`.

## 2026-11-08 - ARIA semantics for tab navigation
**Learning:** Custom navigation tabs need semantic `role="tablist"` and `role="tab"` attributes, plus an `aria-selected` value that tracks the active tab. Without them, screen readers cannot reliably identify the tab set or announce which tab is selected.
**Action:** When implementing tab navigation, assign `role="tablist"` to the tab container, `role="tab"` to each tab, and update `aria-selected` whenever selection changes.

## 2026-11-09 - Async export result live-region status, input labeling, and copy affordance
**Learning:** In async-heavy processing apps (like Podcast Magic and autoraffkat), completion states render into initially hidden containers without live-region semantics (`role="status"`, `aria-live="polite"`). Screen reader users receive no auditory announcement that lengthy async tasks finished, and the resulting readonly path input lacked an accessible name and required mouse clicking to select text. Relying solely on "Show in Finder" also breaks workflows where users need to paste the result path directly into terminals or other tools without native OS file manager interaction.
**Action:** Always mark async completion rows with `role="status"` and `aria-live="polite"`, ensure generated path inputs provide `aria-label` and `onfocus` auto-selection, and pair "Show in Finder" with an inline "Copy path" button providing transient confirmation feedback.
