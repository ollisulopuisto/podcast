# Rough Cut Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Take a raw, transcribed `.nhsx` and produce a preliminary edit in
the editor's own style: a new session next to the original. v1 marks each
suggested cut with a marker pair. v2 also writes a copy with the cuts
applied. Each suggestion is scored against the editor's real edit of a
held-out episode before it is trusted.

**Depends on:** [`2026-10-05-edit-diff.md`](2026-10-05-edit-diff.md). It
supplies the training signal (`EditDiff` of a learning pair), the truth for
scoring (`EditDiff` of the held-out pair) and `nhsx.cut.apply_cuts`.
Supersedes the punted note
[`2026-09-21-transcript-cut-suggester.md`](2026-09-21-transcript-cut-suggester.md),
whose design (markers, never overwrite) carries over.

**Architecture:** Three deterministic steps around one judgement step.

1. **Dump** (code): the raw session becomes a numbered transcript. One line
   per utterance, with speaker (track name), raw-timeline time and stable
   word ids `(file, index)`, plus pauses longer than the editor's p90
   (from the diff stats).
2. **Decide** (LLM): read the dumped transcript and the editor's style
   sheet, and return cuts as JSON: word-id ranges, scope, category, reason,
   confidence. **Word ids only, never times**, so the model cannot produce
   a timestamp that isn't in the session.
3. **Place** (code): turn the word ranges into raw-timeline spans, then move
   each edge into the nearest span where **no** track has activity. This
   uses the signal layer (`nhsx.activity`, edit-diff plan Task 0), not
   Whisper's word gaps. Whisper's times only say roughly where, and the
   microphones say exactly where.
4. **Write** (code): a new `.nhsx` with a `<Marker>` pair per cut (v1),
   and/or `apply_cuts` output (v2), plus `<session>.roughcut.md`, a
   readable cut list.

**Tech Stack:** Python 3.12+, lxml, numpy, pytest, ruff, CalVer. The LLM
step runs first as a Claude Code session working from a prompt file in
this repo. An API call comes later (see "Who decides").

## Prior art (searched 2026-10-05)

- **Hindenburg PRO 2 "Edit with words"**: edit the Manuscript like a text
  document, and deleting text deletes audio. All manual, no suggestions.
  It's the review surface for our output, not a replacement.
  ([hindenburg.com](https://hindenburg.com/hindenburg-pro-2-features/edit-with-words/),
  [Podnews review](https://podnews.net/article/hindenburg-pro-v2-review))
- **Podcast-Cleanup-LLM**: multitrack cleanup with ffmpeg, Whisper and
  llama.cpp. Removes dead air and disfluencies while keeping tracks
  sample-aligned. The closest match. **Read its cut placement before
  Task 4.** It renders audio rather than writing a session.
  ([GitHub](https://github.com/BeppeInfo/Podcast-Cleanup-LLM))
- **RoughCut**: local transcript editor with LLM rough cuts and an MCP
  surface Claude can drive. Video, NLE export, not `.nhsx`.
  ([GitHub](https://github.com/PaulBratslavsky/roughcut-ai-local-first-editor))
- **Descript, Trebble**: one-click filler/silence removal, inside their own
  editors.

None of them reads or writes Hindenburg sessions, and none learns the cut
rules from the editor's own past edits. Both are the point here. Reuse
ideas, not code.

## Design decisions

- **Markers first.** The editor accepts or rejects each suggestion by ear
  in Hindenburg. A wrong marker costs a second, but a wrong cut costs a
  re-listen of the whole episode. The applied-cut copy (v2) waits until the
  held-out score says it's worth it.
- **The style sheet is written from the diff, not invented.** Labelling
  pass: the LLM puts every removal in the learning pair's `EditDiff` into
  a category, with a one-line reason. The editor reads the result and
  corrects it. That labelled list plus the diff stats is `editing-style.md`:
  categories with examples, pause target, filler policy, cut-point habit.
  It holds episode text, so it stays private and outside the repo. A
  synthetic example goes in the repo.
- **Categories start from the data.** The labelling pass proposes the
  categories. Seed list to give it a vocabulary: `false_start`,
  `retake`, `filler`, `pause`, `tangent`, `chatter` (pre/post-show,
  setup), `crosstalk`, `track_cleanup`.
- **Pause trimming is code, not LLM.** The diff stats give the editor's
  pause target. Gaps over it are shortened deterministically, and no
  model judgement is needed for silence.
- **Turn latency is code, not LLM.** On VoIP episodes, handover gaps get
  tightened to the editor's measured target per direction (edit-diff,
  "Turn latency"). Handovers are rippled on all tracks from B's onset,
  which is the editor's method. Reactions are slipped on their own track
  only, by the episode's measured latency, which is the editor's stated
  default ("remove the delay, move that one clip, keep the rest in
  place"). It's a
  separate pass with its own toggle and its own marker category
  (`turn_gap`), because there are many of them, one per handover. In
  marker mode they're summarised in one line per stretch rather than
  given a marker each. That decision gets revisited once we see how many
  the first episode has.
- **Marker convention**: `<Marker Name="✂ 12 tangent ▶">` at the cut
  start and `<Marker Name="◀ 12">` at the end. Ids are sequential after
  any existing markers. `<Marker>` has no grouping attribute (format doc
  §8), so the shared number does the pairing. **To verify at first
  import:** that Hindenburg shows the names in full and sorts them by
  time.
- **Never overwrite.** The output uses `next_free_path` next to the
  original (podcast-magic `nhsx/write.py:140`).

## Who decides (the LLM step)

v1: **Claude Code, in a session.** A prompt file `prompts/roughcut.md`
holds the task, the JSON schema and the instruction to read
`editing-style.md`. The CLI's `dump` and `apply` subcommands are the
hands. This means no API key, no per-episode billing code, and the
editor can steer mid-run.

v2, only if v1 earns it: an API call from the CLI. The same prompt file
and schema, so the two are comparable on the held-out score. Long
episodes go in chunks with overlap. A 60-minute Finnish conversation is
roughly 9–10k words, and the real count gets measured on the first dump.

Either way, the raw transcript, including what the editor cut as
off-the-record, goes to Anthropic. **The editor decides that before
Task 3.**

## Scoring (the held-out pair)

Truth: `EditDiff(raw_heldout, edited_heldout).removals`, on the raw
timeline. Suggestion: the placed cuts for `raw_heldout`, made without
seeing its edit.

- **By time:** precision = suggested seconds that the editor also cut /
  suggested seconds; recall = the editor's cut seconds that were suggested
  / the editor's cut seconds.
- **By cut:** a suggestion matches a true removal at IoU ≥ 0.5. Precision
  and recall per category.
- **Placement:** for matched cuts, edge error in ms against the editor's
  edges. Reported twice, for edges placed from Whisper times alone and
  for signal-corrected edges, so the gain from the signal layer is a
  measured number rather than an assumption.
- A Markdown table of misses and false positives, with text, for the
  editor to read. Some "false positives" will be cuts the editor would
  accept, so the editor marks those and the score is reported both ways.

No target numbers yet. The first run sets the baseline, and the numbers
go into this file as measurements (repo rule: numbers in comments).

### Task 1: Dump with stable word ids

**Files:** `apps/podcast-magic/src/podcastmagic/roughcut/dump.py`,
`apps/podcast-magic/tests/test_roughcut_dump.py`

Word times in the dump are **signal-corrected**: each word's edges are
snapped to its track's own-voice activity within `WORD_SNAP`. Untranscribed
own-voice sound appears as `[sound 0.4 s]` lines, which marks laughs and
backchannels the model would otherwise not know about. Crosstalk (two
tracks `own` at once) is marked `[overlap]`.

**Red:** a two-track synthetic session, one file per speaker, with
interleaved words. The dump orders utterances by raw-timeline time and
labels them by track name. Word ids are `(file name, index in that file's
transcription)` and stay the same when the session is re-read. A file
that plays twice on the timeline is dumped twice, with ids qualified by
region. A pause above the threshold appears as a `[pause 4.2 s]` line.

### Task 2: Cut JSON — schema and validation

**Red:** reject a range whose start id comes after its end id, an unknown
id, an unknown category, or overlapping cuts. Accept and normalise a valid
file. The schema lives in one place (`roughcut/schema.py`), and the
prompt file quotes it from there via a test that fails if they differ.

### Task 3: Labelling pass and style sheet

**Files:** `prompts/roughcut-label.md`, `prompts/roughcut.md`,
`roughcut/style.py` (renders `editing-style.md` from the labelled
`EditDiff` and its stats).

**Red:** `style.py` renders a known labelled fixture to a known Markdown
string: category counts, two examples each, pause target = the editor's
edited-timeline p90, and the filler table.

Then by hand, on the learning pair: run the labelling, have the editor
correct it, and record how many labels the editor changed. That count is
the first measurement of the labelling pass.

### Task 4: Placement into shared silence

**Files:** `roughcut/place.py`

Read Podcast-Cleanup-LLM's cut placement first.

**Red** (synthetic WAVs, as in edit-diff Task 0):
- a cut ending mid-word on track A extends to the end of that word's
  **activity**, not its Whisper end. Fixture: Whisper says the word ends at
  2.00, the tone ends at 2.09, and the edge lands after 2.09.
- an edge inside a gap where track B is speaking (crosstalk) moves to the
  nearest span quiet on all tracks, within `MAX_SHIFT` (0.5 s, a guess).
  If no such span exists, the cut is **flagged, not placed**.
- bleed is not activity: track A's voice leaking 13 dB down into track B
  does not count as B speaking (own vs active, speechmix's dominance rule)
- a breath with no Whisper word stops the edge from landing on it
- the final edge is `refine_edge`'s lowest-energy point, offset by the
  editor's measured habit from the diff stats (e.g. 120 ms after the last
  activity), not the gap's midpoint

### Task 4b: Turn-gap tightening

**Files:** `roughcut/turns.py`

**Red:**
- A→B handovers of 0.9 s with a target of 0.4 s: each gets a ripple at
  B's onset, shifting all tracks by −0.5 s. Material before the onset is
  untouched, and everything after it, on every track, moves.
- a target below zero (the editor's measured overlap) gives a ripple
  larger than the gap, and the result has A's tail and B's head
  overlapping by exactly that much
- a handover where B's first sound is a breath (`[sound]`): the target is
  measured to the breath, not to the first word
- a handover already at or under the target is left alone
- B→A handovers use their own target, not A→B's
- after tightening, no handover overlaps unless the editor's measured
  overlap tolerance allows it
- a session with no asymmetry beyond `LATENCY_MIN` (100 ms, a guess)
  reports "no VoIP latency detected" and does nothing
- **reactions:** found from the signal, not the transcript, because
  Whisper misses laughter: a short own-voice run on B while A holds the
  turn. Fixture: a laugh on B landing 0.5 s after A's punchline, on top
  of A's next phrase, with a measured latency of 0.4 s. The output is a
  one-track slip of the reaction alone, by the latency: B's region split at shared
  silence on B around the laugh and moved 0.4 s earlier, with A
  untouched. If B's track has no silence within `MAX_SHIFT` to split at
  (the laugh runs straight into B's own speech), it's flagged, not
  placed.
- with no edited pair, the target comes from the episode's own latency
  estimate (edit-diff, reaction delays). The report says which source
  was used.

In marker mode, every reaction slip gets a marker (`↶ 7 laugh −0.4 s`).
These are few and audible, and each is worth an ear.

### Task 5: Markers writer

**Red:** writing three cuts into a session that already has two markers
produces exactly six new `<Marker>`s with ids 3–8, times on the raw
timeline formatted the way `nhsx.read.seconds_to_time` formats them, and
leaves every other element byte-identical. Then by hand: open it in
Hindenburg and verify the marker convention (see Design decisions).

### Task 6: Scorer

**Files:** `roughcut/score.py`

**Red:** fixtures with known overlaps give exact precision and recall by
time and by cut: a 10 s truth with a 5 s suggestion inside it gives time
recall 0.5, time precision 1.0 and IoU 0.5, which counts as a match.
Per-category breakdown, and the "editor accepts" re-score.

### Task 7: CLI and the first real run

`uv run roughcut dump|apply|score`. Then:

1. diff + label the learning pair, which gives `editing-style.md`
2. dump the held-out raw session, decide (Claude Code session), apply
   (markers)
3. score against the held-out edit and write the numbers here
4. the editor reviews the marker session in Hindenburg and notes what was
   useful

### Task 8 (v2, gated on Task 7's numbers): applied-cut copy

`apply --cut` writes the `apply_cuts` output with `CROSSFADE` (10 ms, a
guess, to be measured by listening) at each join. Verify by rendering and
listening to every join. A join with a level jump over 3 dB between the
two sides is listed for the editor.
