# ASR shared boundary audit (2026-10-30)

## Scope and provenance

The primary checkout is at `9d7f6665`, with substantial uncommitted Colab and wordalign work. This audit reads that work without changing it. Podcast Magic's Ultra and Orukeet adapters are absent at this checkout's HEAD; the handoff's source commit `5a179e6f` contains them, so observations about those adapters refer to that commit. The local Orukeet route is currently untracked, not a claim about clean main. No hardware or live Colab inference was performed.

## Recommendation

The smallest useful shared boundary is pure, standard-library **segment and word transformation**, not a shared engine interface. Keep inference, audio conversion, availability, progress, cancellation and model lifetime in each host. First consolidate Orukeet sentence-to-word alignment inputs in `packages/wordalign/src/wordalign.py`: the current working copy's `align_segments` can derive words from sentence text, whereas Podcast Magic at `5a179e6f` constructs provisional sentence-boundary word seeds in `transcribe/backends/orukeet.py`. Verify both call paths on the same sentence fixtures, including missing/failed CTC alignment, before removing either adaptation. This is the existing shared implementation, already uploaded for remote alignment; it avoids inventing another runtime abstraction.

Only extract additional pure normalization if parity tests establish identical intended semantics. `colab-transcribe/src/colabtranscribe/colab/pipeline.py:words_document` sorts, floors and resolves overlaps for the Kuulas JSON contract, while `apps/podcast-magic/src/podcastmagic/transcribe/backends/base.py:words_from_segments` builds `nhsx.Word` values and `nhsx/write.py` owns session overlap handling. They are different output boundaries: replacing them wholesale would silently change times and cache/raw data. A small standalone module could share narrowly defined token/segment conversion, with host-specific output adapters retained. Do not conflate local Parakeet MLX token joining with Photon Ultra: they are different engines and their result shapes differ.

If a new shared file is justified, follow the existing single-file `silencelearn`/`wordalign` pattern: declare a workspace dependency, upload the exact installed module alongside `/content/pipeline.py` before execution, and test import in an isolated directory with no workspace. Update **both** `driver.plan_commands` branches (Drive and direct), `plan_audio_commands`, and exercise Drive fallback `direct_tail`, session reuse and dry run. The audio plan intentionally omits silencelearn and uploads wordalign only for `--align`; a mandatory new import requires unconditional upload in every applicable plan. Test packaging and absent-module failures as well as ordering. Avoid a dependency on app modules, NumPy, torch or a particular model SDK in the shared pure module.

## Route and contract differences

- Podcast Magic `backends/mlx.py` and `faster.py` consume decoded arrays; MLX must not receive a path because bundled ffmpeg is not on PATH. At `5a179e6f`, `backends/audio.py`, `orukeet.py` and `ultra.py` bridge arrays to WAV; Orukeet emits sentence-derived seed words and `transcribe/run.py` requires alignment, while Ultra returns Photon word timestamps. Its options, fingerprint, raw cache, progress/cancellation and session write are app contracts. Do not silently promote seeds to actual word times.
- Current local `colabtranscribe/orukeet.py` uses an installation receipt, ffmpeg conversion and `wordalign` CTC; it fails when any word cannot align, producing `timing="orukeet-ctc"`. `colabtranscribe/parakeet.py` uses `parakeet-mlx` and joins sentence tokens; this is Parakeet TDT, not Photon Ultra. Both use `pipeline.words_document` and local event/output paths, but their failure and progress behavior differ. Preserve those distinctions unless explicitly changed and tested.
- `colab/pipeline.py:transcribe_file` calls Photon CUDA for Whisper or Ultra and requests word timestamps; it currently ignores language and prompts, reports ignored prompts, and errors on missing words. Photon Whisper and local MLX/faster Whisper have different option support and cannot be treated as equivalent just because the model family matches. The local working copy accepts legacy model aliases that resolve to Ultra; model names and aliases need explicit compatibility tests before changes.
- `driver.py` uploads the pipeline for every remote route; `plan_commands` uploads silencelearn for both transfer methods, and `plan_audio_commands` conditionally uploads wordalign. `--source audio` has its own direct transfer and output plan. Retain `<stem>.words.json`, its version, language, timing, rejected and word fields, monotonic `PROGRESS`, exit codes, SIGTERM and schema-1 `@@kuulas` events; preserve cleanup of stale output. Alignment runs separately with its own torch environment. Remote support must not rely on the local workspace existing in Colab.

## Validation for a follow-up change

Start with failing tests for equivalent sentence inputs across the two Orukeet adapters, including empty sentences, punctuation, invalid and rejected alignment, and non-overlap/timing expectations. Add isolated uploaded-file execution and command-plan coverage for every route when sharing a file. Run member tests and root Ruff per repository rules. A real Apple Silicon model run and a real Colab GPU run are separate checks; mocked tests cannot establish model accuracy, long-audio behavior, runtime compatibility or performance.
