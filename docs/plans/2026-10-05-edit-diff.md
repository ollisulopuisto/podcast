# Edit Diff Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Given a raw `.nhsx` and the same episode as the editor finished it,
say exactly what the editor did: which spans of which source files were
removed, moved or kept, which words they held, and what the editor's habits
are (pause length left, fillers kept, where a cut lands relative to words).
This is the measurement the rough-cut suggester
([`2026-10-05-rough-cut.md`](2026-10-05-rough-cut.md)) learns from and is
scored against. It also answers the "rules TBD" in
[`2026-09-21-transcript-cut-suggester.md`](2026-09-21-transcript-cut-suggester.md):
the rules are whatever the editor actually does.

**Architecture:** Pure session-to-session comparison in `packages/nhsx`
(`diff.py`), with no audio decoding. Every region names a source file (`Ref`)
and a span of it (`Offset`, `Length`). So the edited session states, per
source file, which file-time intervals survived and where they sit on the
new timeline. The raw session states the same for the start point. Removed =
raw intervals minus edited intervals, per file. The raw session's
`<Transcription>` words (file time, §4 of the format doc) give each removed
interval its text. A round-trip check proves the diff is complete: applying
the diff's cuts to the raw session must reproduce the edited session's
region layout.

**Tech Stack:** Python 3.12+, lxml (already used by `nhsx.read`), pytest, the
repo's red-green + ruff + CalVer rules (`CLAUDE.md`).

## Facts this plan rests on (verified in code / docs)

- `nhsx.read()` gives `Session.files` (`FileInfo`: `id`, `name`, `words()`
  in **file time**) and `Session.tracks` → `RegionInfo(ref, start, length,
  offset)`. `start`/`length` are timeline, `offset` is file time —
  `packages/nhsx/src/nhsx/read.py:153–212`.
- A word at file time `s` plays at timeline `Start + (s − Offset)` of the
  region it falls in. The same file can appear several times —
  `docs/hindenburg-nhsx-format.md` §4, `apps/podcast-magic/CLAUDE.md`.
- `Session.file_by_name()` matches pool files by name, exact first and then
  case-insensitive (read.py:189). `Id`s are per session and **must not**
  be used to pair files across two sessions.
- Omitted time attributes are zero (format doc §3). `nhsx.read` already
  handles this.
- Fades come in two spellings, `FadeIn`/`FadeOut` attributes and `<Fade>`
  children, and region gain in two, `Gain`/`ClipGain` (format doc §6–7).
  The diff records them but does not learn from them in v1.

## Signal layer: what the microphones say, not only what Whisper says

Whisper's word times are an estimate. Edges can be off by a word's
attack, and breaths, laughs and short "mm"s often have no word at all. The
editor cuts by ear, against the signal. So cut-point and pause statistics
measured against Whisper's times would describe Whisper's errors as much
as the editor's habits. Every statistic in this plan is therefore measured
against **per-track activity**, with Whisper's times kept alongside for
comparison.

- **Reuse, don't write.** `speechmix.rms.envelope_for` returns a cached
  RMS curve per file (8 kHz decode, 20 ms hop, about a megabyte per track).
  That stays within podcast-magic's memory ceiling: two files open at a
  time, and 5 tracks × 75 min would be 575 MB as stems
  (`apps/podcast-magic/CLAUDE.md`, "speechmix on tuotu"). The decision rule
  is speechmix's: activity above the track's own floor +
  `grid.FLOOR_MARGIN_DB` (12 dB), and *own voice* only within
  `masks.DUCK_DOMINANCE_DB` of the loudest track. The latter matters
  because on a two-mic recording, half of what is loud on a track is the
  other person (grid.py docstring: 74 % called speech vs 53 % actually the
  owner's).
- **Files to timeline:** each file's curve is mapped through its regions
  (`Start + (t − Offset)`), giving per track a 20 ms timeline grid of
  `active` and `own`.
- **Finer edges where it matters:** 20 ms is enough for pauses but coarse
  for a cut edge. At each cut edge, a local search at full sample rate
  (±40 ms) finds the lowest-energy point. That's the edge position used in
  stats and placement.

What it adds to the output:

- **Whisper's timing error, measured:** for every word, the distance from
  its start/end to the nearest own-voice activity edge on its track, within
  `WORD_SNAP` (150 ms, a guess). Median, p90 and the share outside the
  window. This number is reported per pair and goes into this file. It
  says how much the transcript can be trusted for placement.
- **Untranscribed sound:** own-voice activity runs with no word over them
  (≥ `MIN_SOUND` 120 ms). In each removal's text they show as `[sound
  0.4 s]`, so a cut breath or laugh is visible. They count separately in
  the stats ("editor removes breaths: n / m").
- **Signal-based pauses:** a pause is a span where no track has own-voice
  activity, not a gap between Whisper words. Both are reported, and the
  difference between them is a measurement in its own right.
- **Cut edges against the signal:** for each cut edge, whether it lands in
  shared silence, the distance to the last activity before it and the
  next after it, and the level at the edge. These are the editor's
  placement habits ("leaves ~120 ms after the last word"), measured
  instead of guessed.

## Turn latency (VoIP)

On a VoIP recording, each handover to the remote speaker carries the call's
latency: B answers, but A's track hears it a round trip late, so the
silence between turns is longer than it was in the room. The editor
tightens these as a matter of routine. That's a habit to measure, separate
from cutting content.

- **Handover gaps by direction.** On the signal layer, a handover is the
  span from the end of one speaker's own-voice activity to the start of
  the next speaker's. Report the distribution (median, p10, p90) per
  ordered pair (A→B, B→A) in raw and in edited. Latency shows up as
  **asymmetry**: in raw, handovers into the remote speaker are longer. In
  edited, they're not, if the editor corrected them. Raw-minus-edited per
  direction is the measured adjustment.
- **Same-speaker pauses are the control.** A pause inside one speaker's
  turn has no latency in it. If the editor shortens handovers but not
  these, that's latency correction rather than general tightening. Both
  are reported side by side.
- **How the editor does it (the editor's own account, 2026-10-05).**
  - **Handovers:** select everything from B's next utterance onward, on
    every track, and move it left until A's end and B's start meet the way
    they should. That's a **ripple**: one point `T` (B's onset), one shift
    `d`, applied to all tracks. When `d` is larger than the silent gap, A's
    tail and B's head end up overlapping across tracks, and that's
    intended. The diff reports it as `ripple {at, shift}` tagged
    `turn_gap`, not as a removal, and measures the handover after the
    edit: gap or overlap in ms, from the signal. The editor's target is
    that post-edit distribution.
  - **Reactions:** move only the reaction's clip earlier on its own track,
    and leave everything else on all tracks in place. That's a **slip**:
    one track's region split around the reaction and moved, with `Offset`
    consistent, so nothing is removed. A slip is neither a removal nor a
    move, so it gets its own list: `slips: {track, raw_start, span,
    shift_s}`. The amount varies by judgement ("when should the laugh
    happen"), so the diff reports the distribution of shifts, not one
    number.
- **[unknown, measure first]** What Hindenburg writes when a ripple moves
  material on A's track over A's own earlier region: does it trim the
  region underneath, or layer both? It decides whether A's tail survives a
  ripple that's larger than A's silence. Check with a hand-made session in
  Hindenburg before Task 6, and add the answer to the format doc.
- **Reactions show latency most.** A laugh, "mm" or "joo" from the remote
  speaker lands a round trip after the line that caused it. Often it lands
  on top of the speaker's *next* sentence, where it sounds like a reaction
  to the wrong thing. A gap cut can't fix that, because the other speaker
  is still talking. The fix is to slip only the reaction earlier. So:
  - a **reaction** is a short own-voice run on one track (≤
    `REACTION_MAX`, 3 s, a guess). It's either untranscribed `[sound]`
    or laughter/backchannel tokens (`haha`, `mm`, `joo`, `nii`; list in
    a constant, extended from data). It falls while another speaker holds
    the turn or within 1 s of the end of their turn.
  - for each reaction: its delay from the end of the nearest preceding
    activity run on the other track (the punchline). In raw and edited,
    per direction.
  - the edit side: whether it was slipped (one-track region split around
    the reaction and moved, a `slip` with a short span), by how much, and
    whether that amount matches the handover adjustment. If it does,
    that's one latency figure measured two ways.
  - **Whisper doesn't transcribe laughter.** So reactions are found from
    the signal: a short own-voice run on one track while another track
    holds the turn, with or without words. The editor recognises them the
    same way, by eye.
- **Latency estimate, per episode, needing no edit.** The editor's default
  for a reaction is "remove the delay between the speakers", so the delay
  has to be measured. Three ways, in order of directness, all reported so
  they can be checked against each other:
  1. **Echo lag**, if there is any. When the remote speaker isn't on
     headphones, A's voice comes back on B's track one round trip late.
     Envelope cross-correlation of A's solo stretches against B's track
     gives that lag directly. Reuse `speechmix.chain.lag_samples` (FFT,
     envelope-based) and the solo-stretch selection in
     `speechmix.debleed`. No echo means no estimate, and it's reported as
     absent, not as zero.
  2. **Handover asymmetry**: median A→B handover minus median B→A.
  3. **Reaction delay asymmetry**: the same, over reaction onsets after
     the punchline.

  These three agreeing within ~50 ms is the confidence check. Where an
  edited pair exists, the editor's median slip is compared with them.
- **Overlap created by tightening.** If tightening makes the speakers
  overlap on the edited timeline where they didn't in raw, count it. The
  editor's tolerance for overlap at handovers is part of the habit.

## Preconditions on the input pair (checked, not assumed)

1. The edited session still references the **same source files** as the raw
   one, matched by name. If the editor consolidated or bounced, the regions
   point at new files and there is nothing to diff by provenance. The tool
   says so and stops: it reports which edited regions reference files
   missing from the raw pool. Audio alignment for that case is out of scope
   for v1.
2. The raw session has a transcription. If it doesn't, run podcast-magic's
   transcription on the raw session first. The tool refuses rather than
   diffing without words.

## Design decisions

- **Provenance, not alignment.** No audio cross-correlation and no
  transcript string matching. Region attributes give exact answers, and an
  alignment would only be an estimate of them.
- **The unit is a source-file interval.** Timeline positions move with
  every ripple, but a file interval doesn't. Each removal is reported as
  `(file name, file_start, file_end)`, plus where it sat on the **raw**
  timeline. The scorer in the rough-cut plan compares cuts on the raw
  timeline.
- **Global vs one-track removals.** A cut the editor made across the whole
  conversation removes the same raw-timeline span from every speech track.
  Deleting a cough or bleed on one track removes it from that track only.
  These are different decisions, so they are two categories (`global`,
  `track`), told apart by checking the raw-timeline overlap across tracks
  (tolerance `TRACK_ALIGN_TOL`, initially 20 ms, to be measured on the
  first pair).
- **Moves are reported, not learned.** If the kept intervals appear in a
  different order on the edited timeline than in the raw one, that's a
  restructure. It goes in the report as `moved` and is excluded from the
  cut statistics.
- **Added material** (files in the edited pool that aren't in the raw one:
  music, intro, ads) is listed as `added` and ignored.
- **Private by default.** Reports contain the episode's words. They are
  written next to the session (`<session>.editdiff.json`, `.md`), never
  into the repo. Test fixtures are synthetic.

## Output

`EditDiff` (dataclass, serialised to JSON):

- `removals`: list of `{scope: global|track, track, file, file_start,
  file_end, raw_start, raw_end, words: [..], text, before, after}`. `before`
  and `after` are the 10 surrounding words, for context.
- `moves`, `added`, `unmatched_files`
- `stats`, measured on what was kept and cut:
  - pause distribution in raw vs edited (gaps between consecutive words of
    the conversation, all tracks merged): median, p90, max
  - per filler token (`öö`, `tota`, `niinku`, `um`, `uh`, …; list in a
    constant, to be extended from data): count in raw, count removed
  - cut-point placement: distance from each cut edge to the nearest word
    edge, and whether it lands in a gap
  - seconds removed and the raw/edited durations
- A Markdown rendering for a human to read: every removal with its text and
  context, in raw-timeline order.

Categorising removals (false start, tangent, chatter, …) is **not** done
here. It's a judgement on text and belongs to the rough-cut plan's
labelling pass. This module stays deterministic.

### Task 3: Global vs track removals, moves

**Red:**
- two tracks, the same 10 s removed from both → one `global` removal
- 1 s removed from track B only → one `track` removal on B
- edited order B-before-A of two kept intervals → one `move`, zero
  removals
- track B's region starts 0.4 s earlier relative to track A in edited,
  with nothing removed → one `slip` (B, −0.4 s), zero removals and zero
  moves
- a 0.6 s global removal whose span runs from A's last activity to B's
  first → tagged `turn_gap`
- turn stats: a fixture with A→B gaps of 0.9 s and B→A gaps of 0.3 s in
  raw, A→B tightened to 0.4 s in edited, reports the asymmetry and the
  0.5 s adjustment per direction. Same-speaker pauses unchanged.
- reaction slip: a 0.8 s `[sound]` on B starting 0.5 s after A's phrase
  ends, overlapping A's next phrase. Edited splits B's region around it
  and moves it 0.4 s earlier. Result: one reaction `slip` (B, −0.4 s,
  span 0.8 s), reaction delay 0.5 → 0.1 s, zero removals.

### Task 4: Words and context for each removal

**Red:** the raw file has a `<Transcription>`. A removal 20–30 s returns
exactly the words whose midpoint falls inside 20–30 file seconds, plus 10
words of context on either side. A word straddling the cut edge is
reported in `edge_words` and not in `words`, because it shows a cut
landing mid-word.

### Task 5: Stats

**Red:** a fixture with known gaps (0.2, 0.5, 1.5, 3.0 s) where the edit
shortens the 3.0 s gap to 0.6 s: the raw and edited pause stats report
those exact numbers. A fixture with three `öö`, one of them removed: the
filler table says 3 / 1. Pauses are measured from activity (Task 0). A
fixture whose Whisper gap is 1.0 s but whose signal gap is 0.7 s (a
trailing breath) reports 0.7 as the signal pause and 1.0 as the
transcript pause. A cut edge placed 120 ms after a tone's end reports
"in silence, 120 ms after activity".

next to the existing `nhsx` entry points, which keeps Finnish code
